App map · snapshot

stackfit

Paste a hackathon link and describe an idea. StackFit picks the lightest free stack, one pick per layer, next to what an AI chat would usually suggest. Then it reads each provider's own pricing page live and tags every fact verified, vague or not found, with its source.

Built from commit df7de04 on 10 Oct 2026. Code can drift from this map after that.

The main pieces

The page

Vite + React in web/src/. Sends requests, shows each stage as it arrives, draws the stack cards.

The API

One Hono app in server/app.ts with two routes, POST /api/hackathon and POST /api/stack. Both stream newline-delimited JSON events. On Vercel, api/[[...route]].ts hands every request to it.

Outside services

Gemini (reads rules, picks the stack, reads pricing pages with URL context) and Exa (backup search, and backup page fetch when a site blocks Vercel). Nothing is stored.

One action, end to end: "Pick my stack"

Reference route (3 stops)

Not toured together; open these in your editor to follow the action yourself.

Stop 1 · the click

web/src/App.tsx, search function pickStack

Saves the idea, clears the old result and calls stack.run("/api/stack", …). useRun (web/src/hooks/useRun.ts) reads each streamed line and updates the stage log; the result event fills the cards.

Stop 2 · the route

server/app.ts, search app.post("/stack"

Checks the input (idea 10 to 1200 characters), sends "Working out what the idea needs", calls pickStack, then checkAll, then sends the result. With previous and edits in the body it calls refineStack instead and rechecks only changed layers.

Stop 3 · the tags

server/lib/checkFacts.ts, search function tagFacts

The model only reports what the page said. Code sets the tag: verified needs the value stated on the page, a digit in it, and a source on the provider's own domain. Anything else found is vague; nothing found is not found.

To change this, start here

  • How picks are chosen (lighter, no card, no deprecated tools): LAYER_RULES in server/lib/pickStack.ts.
  • Which facts get looked up: SERVICE_FACTS and LIBRARY_FACTS in server/lib/checkFacts.ts.
  • When a fact counts as verified: tagFacts in server/lib/checkFacts.ts.
  • Lookups at once and timeout: AT_ONCE and LOOKUP_TIMEOUT_MS at the top of server/lib/checkFacts.ts.
  • Colors and fonts: the theme tokens in web/src/index.css.
  • The copied prompt: buildPrompt in web/src/lib/prompt.ts.
  • Gemini model and retry: server/lib/gemini.ts.

A practice to reuse

Let the model report; let code decide. In slice 3 a test run picked the Claude API and tagged a fact "verified" that came from a consumer pricing page. The fix (see devpost/checklist.md → Revisions, slice 3) was to keep the model's job to "what does the page say" and move the judgment into tagFacts: a fixed rule about numbers and official domains.

On another project: when an LLM's answer drives a label, score or yes/no that users will trust, ask it for the raw evidence and write the rule that turns evidence into the label in code. The rule is easy to test, and it can't talk itself into a better grade.
